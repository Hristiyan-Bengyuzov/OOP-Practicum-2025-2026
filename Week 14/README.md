# Система за управление на студенти

Да се разработи система за управление на студенти и проверка дали даден студент отговаря на всички критерии за допускане до финален държавен изпит. Системата работи с академична информация за студентите и набор от конфигурируеми изисквания.

---

## Студенти

Реализирайте клас `Student`, който представя академичния профил на студент.

Всеки студент съдържа:

- факултетен номер
- име
- списък от взети дисциплини
- брой натрупани кредити
- среден успех

---

## Дисциплини

Реализирайте клас `Course`, представящ учебна дисциплина.

Всяка дисциплина съдържа:

- име
- брой кредити
- категория (`Programming`, `Mathematics`, `AppliedMathematics`, `Other`)
- дали е задължителна или избираема

---

## Изисквания за допускане

Реализирайте обща абстракция `AdmissionRequirement` за изискване за допускане до финален изпит.

Всяко изискване трябва да може да провери дали даден студент отговаря на него, чрез метод `check(const Student&)`, който като резултат връща причината, поради която студентът не отговаря на изискването (или празен резултат при успех).

Йерархията трябва да поддържа полиморфно копиране чрез виртуален метод `clone()`.

Изискванията могат да бъдат следните:

- **минимален брой натрупани кредити** - проверява дали студентът има поне търсения брой кредити, зададен в изискването
- **взети конкретни дисциплини по имена** - проверява дали студентът е взел всички дисциплини, чиито имена са зададени в изискването
- **минимален брой дисциплини от категория** - проверява дали студентът е взел поне зададения брой дисциплини от дадена категория
- **минимален брой кредити от избираеми** - проверява дали кредитите от избираеми дисциплини надвишават зададения минимум
- **минимален среден успех** - проверява дали средният успех на студента е поне зададената стойност
- **взети всички задължителни дисциплини** - проверява дали студентът е взел всички задължителни дисциплини в системата

Системата трябва да бъде проектирана така, че добавянето на ново изискване да не изисква промяна в логиката на `AdmissionService`.

### Предикатно изискване

В допълнение към горните конкретни изисквания, системата трябва да поддържа и обобщено предикатно изискване `PredicateRequirement`, конфигурирано чрез `std::function<bool(const Student&)>` и придружаващо съобщение за неуспех. Това позволява добавяне на произволни условия, без да е необходимо създаването на нов клас:

```cpp
PredicateRequirement hasEnoughCourses(
    [](const Student& s) { return s.getCourses().size() >= 10; },
    "Student must have taken at least 10 courses."
);
```

## Конфигуриране на изисквания

Различните изисквания трябва да могат да бъдат конфигурирани директно чрез конструктори.

```cpp
MinimumCreditsRequirement minimumCredits(240);

MinimumCoursesFromCategoryRequirement programmingCourses(
    CourseCategory::Programming, 5
);

MinimumAverageGradeRequirement minGrade(4.50);

PredicateRequirement customCheck(
    [](const Student& s) { return s.getCredits() % 30 == 0; },
    "Credits must be divisible by 30."
);
```

Ако дадено изискване е конфигурирано с невалидни параметри (например среден успех извън диапазона [2.00, 6.00]), системата трябва да сигнализира за грешна конфигурация:

```
Invalid requirement configuration: minimum average grade must be between 2.00 and 6.00.
```

## Service за проверка на допускане

Реализирайте отделен клас `AdmissionService`, който отговаря за изпълнението на всички изисквания.

Обекти от тип `AdmissionService` трябва да могат да се копират. 

Изискванията се добавят полиморфно:

```cpp
admissionService.addRequirement(minimumCredits);
admissionService.addRequirement(allMandatoryCoursesRequirement);
admissionService.addRequirement(programmingCourses);
admissionService.addRequirement(minGrade);
admissionService.addRequirement(customCheck);
```

При проверка на студент service-ът трябва:

- да обходи всички добавени изисквания
- да извика всяко изискване върху студента
- да събере всички съобщения от всички непокрити изисквания
- да върне резултат, който позволява на извикващия код да разбере дали студентът е допуснат и ако не е - защо

Важно е service-ът да не спира при първото непокрито изискване - всички причини трябва да бъдат събрани и върнати.

---

## Резултат от проверката

Тъй като недопускането е очакван изход, а не системна грешка, реализирайте отделен клас `AdmissionResult`.

Резултатът предоставя:

- дали студентът е допуснат
- списък със съобщения за непокрити изисквания

Примерен изход при недопускане:

```
Student is not admitted to the state exam:
- Student has 210 credits, but at least 240 are required.
- Mandatory course not passed: Operating Systems.
- Student average grade is 4.20, but at least 4.50 is required.
```

Примерен изход при допускане:

```
Student is admitted to the state exam.
```

## Система за студенти

Реализирайте клас `StudentSystem`, който управлява колекция от студенти.

Системата съдържа колекция от регистрирани студенти, както и `AdmissionService`, чрез който се извършват проверките за допускане.

Системата трябва да предоставя достъп за четене до текущите студенти и да поддържа следните операции:

- добавяне на студент - ако вече съществува студент със същия факултетен номер, системата трябва да сигнализира за грешка
- премахване на студент по факултетен номер - ако студентът не е намерен, системата трябва да сигнализира за грешка
- `operator[]` за намиране на студент по факултетен номер (такъв може да има, може и да няма)
- проверка дали студент е допуснат до финален изпит - използва вътрешния `AdmissionService` и връща `AdmissionResult` с всички причини при недопускане

Трябва да има възможност един и същи `AdmissionService` да бъде споделян между няколко отделни `StudentSystem` обекта. В същото време различните системи могат да използват различно конфигурирани service-и - например един изисква 240 кредита, друг - различен брой или различни категории дисциплини. Това се постига чрез различна конфигурация на service-а, без промяна в логиката на системата.

### Допълнителни операции с `std::function`

Системата трябва да поддържа и следните операции, приемащи `std::function` като параметър:

**Филтриране** - връща списък от студенти, отговарящи на зададено условие:

```cpp
std::vector<Student> filter(std::function<bool(const Student&)> predicate) const;
```

```cpp
auto goodStudents = system.filter([](const Student& s) {
    return s.getAverageGrade() >= 5.00;
});
```

**Сортиране** - връща сортиран списък според зададен компаратор, без да променя вътрешното състояние на системата:

```cpp
std::vector<Student> sorted(std::function<bool(const Student&, const Student&)> comparator) const;
```

```cpp
auto byGrade = system.sorted([](const Student& a, const Student& b) {
    return a.getAverageGrade() > b.getAverageGrade();
});
```

**Трансформация** - прилага зададена функция върху всеки студент и връща резултатите като нов списък:

```cpp
template <typename T>
std::vector<T> map(std::function<T(const Student&)> transform) const;
```

```cpp
auto names = system.map<std::string>([](const Student& s) {
    return s.getName();
});
```

**Действие върху всеки студент** - прилага зададена функция върху всеки студент в системата, например за извеждане или логване:

```cpp
void forEach(std::function<void(const Student&)> action) const;
```

```cpp
system.forEach([](const Student& s) {
    std::cout << s.getFacultyNumber() << ": " << s.getName() << "\n";
});
```
